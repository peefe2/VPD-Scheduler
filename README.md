# VPD Scheduler

머신러닝 기반 수증기압차(VPD) 예측 모델 구축 및 스마트팜 의사결정 지원 캘린더 서비스 (졸업과제)

온실의 온도·습도·CO2로 VPD를 계산하고, 날짜별로 적정 대역 안에 있던 시간을 캘린더로 돌아보게 합니다.
+1h/+3h 뒤 VPD 예측은 **그 온실 실측으로 "현재 값을 그대로 쓰는 방법(persistence)"보다 낫다고
확인된 뒤에만** 보여줍니다. 설비를 자동으로 제어하지 않으며, 조치는 항상 사람이 결정합니다.

설계·결정 사항과 근거 데이터는 [CLAUDE.md](CLAUDE.md)에 있습니다.

## 화면

| 화면 | 내용 | 대상 온실 |
|---|---|---|

| 캘린더 | 칸 색 = 낮(09~17시) 대역 안 비율 5단계, 칸 아래 = 밤 과습(대역 아래) %. 날짜를 누르면 24시간 VPD 곡선 | 전체 |
| 오늘 | 현재 VPD, +1h/+3h 값, 현재 상태가 몇 시간째인지, 최근 24시간 그래프, 최우선 조치 후보 1개 | 수집 API·재생 |
| AI 어드바이저 | 등록 설비 안에서 조치 후보 3개와 근거, "이번 정시에 한 조치" 기록(후보 / 후보에 없는 조치 / 안 함 + 이유)과 그 정시 → 2시간 뒤 실측 VPD, 질문하기. 공개 데모에서는 기록·질문이 브라우저마다 따로 저장 | 수집 API·재생 |
| 온실 설정 | 정보 수정, 적정 대역 변경(오늘부터 적용 / 처음부터 정정)과 변경 이력 | 전체 |

## 핵심 규칙

- **VPD 계산:** SVP = 0.6108·exp(17.27T/(T+237.3)), VPD = SVP·(1 − RH/100) kPa. 매 정시의 첫 실측값만
  쓰고(평균 아님), 빠진 정시는 보간하지 않습니다.
- **기본 적정 대역 0.5~1.5 kPa:** 문헌 근거로 정한 값이며, 온실 데이터에 맞춰 고르지 않습니다.
- **자동 전환:** 지평마다 처음 14일은 "학습 중", 이후 7일 단위로 판정해 3주 연속 개선이면 "모델 사용"
  (빨라야 35일째), 한 주라도 못하면 즉시 persistence로 돌아갑니다. CO2가 없는 온실은 모델을 쓰지
  않습니다. +6h는 백테스트에서 검증용으로만 계산하고, 오늘 화면·어드바이저에는 쓰지 않습니다.
- **성능 수치:** 화면에는 온실 하나씩 학습에서 빼고 잰 값(LOSO)만 씁니다. 연구 데이터 기준 +1h
  개선율은 일반 농가 6곳 +9.7%, 정밀 환경제어 온실 4곳 −10.9%입니다.
- **AI 어드바이저 가드레일:** 근거(사실 시트)에 없는 숫자, 등록하지 않은 설비, 단정적인 표현, 깨진 글자가 나오면
  막고 규칙 기반 안내로 바꿉니다. 대역을 벗어나는 시각은 예측하지 않습니다.

## 진행 상황

- **완료:** 온보딩·CSV 업로드, 캘린더, 자동 전환, 오늘 화면, 수집 API(온실별 토큰 인증),
  재생 모드, AI 어드바이저(규칙 기반 + Gemini 연동, 기본 꺼짐), 적정 대역 변경 이력, 이메일 회원가입·로그인,
  공개 데모 배포, 서비스 소개 화면, 작물·생육 단계별 적정 대역 추천(문헌 근거가 있는 칸만 —
  [research/band_literature.md](research/band_literature.md))
- **진행 예정:** 푸시 알림, 로그인 시도 제한·비밀번호 변경
- **알려진 한계:** 데이터가 가을·겨울뿐이라 여름 고VPD 위험이 덜 반영돼 있습니다. 실제 데이터의 대부분이
  대역 아래(과습)라 캘린더가 대체로 "대역 아래"로 보이는 건 버그가 아니라 데이터 그대로입니다.
  어드바이저의 조치 규칙은 초안이라 재배 전문가 검토가 필요합니다.

## 구조

```
backend/   FastAPI + SQLModel(SQLite) + pandas + LightGBM (uv, Python 3.12)
  app/       VPD 계산, 캘린더 집계, 예측·백테스트, 자동 전환, 오늘 화면, 어드바이저, 대역 이력
  models/    지평별 LightGBM 모델 (+ 데모용 온실별 제외 모델)
  tests/
frontend/  React 19 + Vite + TypeScript + react-router + TanStack Query
research/  모델 학습·검증 스크립트, 대역 추천용 문헌 표 초안
```

## 설치 (처음 한 번)

필요한 것: Git, [uv](https://docs.astral.sh/uv/), Node.js 20 이상

```
git clone https://github.com/peefe2/VPD-Scheduler.git
cd VPD-Scheduler/backend
uv sync
cd ../frontend
npm install
```

## 실행

### 가장 쉬운 방법: `start.cmd` 더블클릭 (Windows)

프로젝트 폴더의 **`start.cmd`** 를 더블클릭하면 "VPD 백엔드"·"VPD 프론트" 창이 열리고, 준비되면
브라우저(http://localhost:5173)가 뜹니다. 끄려면 두 창을 닫습니다.

처음 실행하면 `backend\.env` 를 만들어 메모장으로 엽니다. `GEMINI_API_KEY=` 뒤에 키를 붙여 넣고 저장한
뒤 메모장을 닫으면 계속 진행합니다(키가 없으면 그냥 닫아도 됩니다). 기본 설정(`VPD_DEMO=1`)이면
**"데모 온실 (farm3 재생)"이 자동으로 만들어져** 바로 AI 어드바이저까지 볼 수 있습니다.

### 직접 실행 (터미널 2개)

```
cd backend
uv run uvicorn app.serve:app --port 8000
```

```
cd frontend
npm run dev
```

브라우저에서 http://localhost:5173 을 엽니다. `app.serve`가 `backend/.env`를 읽고, API를 `/api` 아래에
둡니다(프론트 개발 서버가 `/api`를 8000으로 넘김). Windows에서는 `--reload`를 붙이면 코드 변경 후
재시작이 멈추거나 예전 코드로 응답할 때가 있어, 시연 때는 빼는 편이 안전합니다.

### 설정 (`backend/.env`)

`backend/.env.example`을 복사해 `backend/.env`로 저장하고 값을 채웁니다. `.env`는 git에 올라가지 않습니다.

| 항목 | 뜻 |
|---|---|
| `GEMINI_API_KEY` | [Google AI Studio](https://aistudio.google.com/)에서 각자 받는 무료 키. **남에게 공유하거나 git에 넣지 않습니다** |
| `VPD_ADVISOR_LLM=1` | AI 어드바이저가 Gemini를 씀 (없으면 규칙 기반 안내만) |
| `VPD_DEMO=1` | 켤 때 데모 온실을 만들고 지금 시각까지 이력을 채움 |
| `VPD_READONLY=1` | 완전 읽기 전용 — 가입·로그인 포함 모든 쓰기를 막고 질문하기만 열어 둠 |
| `VPD_DATABASE_URL` | DB 주소. 비우면 `backend/vpd.db`(SQLite), 배포는 PostgreSQL(`postgresql://...`) |
| `VPD_ASK_PER_MINUTE` | 1분에 받는 질문 수 상한 (공개 데모에서 무료 키 한도 보호) |

모델은 `VPD_ADVISOR_MODEL`로 바꿀 수 있습니다(기본 `gemini-3.5-flash-lite`, 응답 약 4초).
LLM 답변은 "모델 사용" 상태 지평이 있을 때만 쓰이고, 가드레일을 통과하지 못하거나 호출이 실패하면
규칙 기반 안내로 대체됩니다. 무료 등급은 보낸 내용이 Google 제품 개선에 쓰일 수 있습니다(온실 측정값만 보냅니다).

## 계정 (이메일 가입·로그인)

화면 왼쪽 아래 **회원가입**에서 이메일과 비밀번호(8자 이상)로 가입합니다. 이메일 확인 메일은 보내지
않고, 비밀번호 찾기는 아직 없습니다.

- 온실은 만든 계정만 보고 바꿀 수 있습니다. 로그인하지 않으면 **공개 데모 온실**만 보이고(보기·AI
  질문하기), 데모 온실은 아무도 바꿀 수 없습니다.
- 로그인 기능 전부터 있던 온실은 **처음 가입한 계정**의 것이 됩니다(데모 온실 제외).
- 센서 수집 API는 로그인 대신 온실별 토큰으로 인증합니다(그대로).

## 데모 온실 (자동)

`VPD_DEMO=1`이면 백엔드가 켤 때 연구 데이터(farm3)를 날짜만 오늘로 옮겨 "데모 온실 (farm3 재생)"에
넣습니다. 앞 35일이 지난 이력이라 켜자마자 모델 예측과 AI 어드바이저가 동작합니다. 켜져 있는 동안
새 정시는 들어오지 않으니, 시연 직전에 다시 켜면 그 시각까지 채워집니다.

## 시연: 재생 모드 (직접)

실제 센서 대신 연구 데이터(farm3)를 날짜만 오늘로 옮겨 정시마다 흘려보냅니다. 데모 온실과 달리
켜 두는 동안 매 정시 값이 실제로 들어옵니다.

1. 화면에서 새 온실 등록 — 데모 설정의 학습 온실에 `farm3_2023` 선택
2. 데이터 연결 단계에서 "재생 모드" 선택 → "토큰 발급"을 누르면 토큰이 들어간 명령이 나옵니다.
   세 번째 터미널에서 실행 (토큰은 그 화면에서 한 번만 보이니, 잃어버리면 재발급)

   ```
   cd research
   uv run --project ../backend python replay_ingest.py <온실 id> farm3_2023 --token <토큰>
   ```

   앞 35일 이력을 먼저 보내고, 이후는 실제 시계에 맞춰 매 정시 1건. `--speed 60`이면 1분에 1시간씩
   (표시 시각이 실제보다 앞서 나감). 멈추려면 Ctrl+C.

재생 온실은 모든 화면에 "재생 데이터, 이 온실의 실측이 아님" 안내가 뜹니다.

## 공개 배포 (Render + Neon, 무료)

`Dockerfile`이 프론트를 빌드해 백엔드 한 서버로 묶고, 기본값으로 데모 온실(`VPD_DEMO=1`), 질문 수 상한
(`VPD_ASK_PER_MINUTE=10`), HTTPS 전용 세션 쿠키(`VPD_COOKIE_SECURE=1`)를 켭니다. Render 무료 플랜은
디스크가 유지되지 않으므로 **계정·온실은 Neon(무료 PostgreSQL)에 둡니다.**

1. [Neon](https://neon.tech)에 가입 → 프로젝트 만들기(지역은 가까운 곳, 예: Singapore) →
   **Connection string**(`postgresql://...?sslmode=require`)을 복사
2. [Render](https://render.com)에 GitHub 계정으로 가입 → **New → Blueprint** → 이 저장소 선택
3. `GEMINI_API_KEY`에 Gemini 키, `VPD_DATABASE_URL`에 Neon 연결 주소를 넣고 만들기 — 빌드에 몇 분
   (이미 만든 서비스면 서비스 **Environment**에서 `VPD_DATABASE_URL`을 추가하고 저장 → 다시 배포)
4. 생긴 주소(`https://vpd-scheduler-demo.onrender.com` 같은)를 공유

무료 플랜은 15분 동안 접속이 없으면 잠들어서, 다음 접속 때 깨어나는 데 1분쯤 걸립니다. 방문자 모두가
Gemini 키 하나를 같이 쓰므로, 질문이 몰리면 "1분 뒤 다시"가 뜰 수 있습니다. `VPD_DATABASE_URL`을 비워
두면 서버 안 SQLite를 써서 잠들 때마다 계정·온실이 지워집니다.
